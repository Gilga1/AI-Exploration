# AI Exploration

A shared home for experiments in building, evaluating, and operating AI systems — from agent orchestration and semantic data layers to fine-tuning and production-grade eval harnesses.

This repository is intentionally **not** a single application. `main` is the entry point: a map of active explorations, each developed on its own branch. Clone the branch you need, or use this page to understand how the pieces fit together.

## Vision

We are exploring how to make AI useful in real product workflows — not as one-off demos, but as composable, observable, and trustworthy systems. The projects here share a few themes:

- **Agents that do work** — routing, planning, tool use, and human-in-the-loop where it matters
- **Grounding in data** — semantic layers, connectors, and retrieval that keep answers tied to source truth
- **Rigorous evaluation** — trace-native harnesses that score agent behavior with real LLM judges, not stubs
- **Model adaptation** — fine-tuning smaller models on domain-specific agentic code patterns

Each project below is self-contained. Pick a branch, read its README, and run from there.

### AI Agent Harness

**Branch:** `cursor/agentic-harness`

A generic, plugin-based agent orchestration harness. The core engine only knows interfaces — tools, skills, agents, connectors, workflows, and context packs self-register at bootstrap. Domain logic lives in config, not in core Python.

**What it explores:** tiered routing, multi-step planning with HITL approval, parallel DAG execution, working + episodic memory, and full OpenTelemetry tracing across agent runs.

**Get started:**
```bash
git fetch origin cursor/agentic-harness
git checkout cursor/agentic-harness
# See README.md and SETUP.md on that branch
```

### Agentic RAG Eval Harness

**Branch:** `hermes/eval-harness`

An LLM-driven evaluation harness for agentic RAG systems. Keeps the request path (LangGraph/LangChain) separate from telemetry (OpenTelemetry) and evaluation (DeepEval). Every answer and judge score comes from a real LLM.

**What it explores:** trace-native scoring, async eval pipelines off the hot path, production guards (API-key auth, threshold alerting, judge sampling), and a React dashboard for regression visibility.

**Get started:**
```bash
git fetch origin hermes/eval-harness
git checkout hermes/eval-harness
# See README.md and RUNBOOK.md on that branch
```

### Semantic Layer Shell

**Branch:** `cursor/semantic-layer-shell`

A platform-agnostic semantic layer backed by a Neo4j knowledge graph. AI agents select metrics, measures, and dimensions from the graph; SQL is assembled deterministically in Python — never generated by an LLM.

**What it explores:** graph-backed metadata registries, agent-driven dimension selection, deterministic query assembly, and a pilot deployment for Intelligence Hub.

**Get started:**
```bash
git fetch origin cursor/semantic-layer-shell
git checkout cursor/semantic-layer-shell
# See semantic-layer-shell/docs/setup.md on that branch
```

### Qwen Agentic Fine-Tuning

**Branch:** `cursor/qwen-agentic-ft-setup-7e0b`

Fine-tune **Qwen3.5-2B-Instruct** on LangChain, LangGraph, and Deep Agents code patterns extracted from open-source repos.

**What it explores:** automated training-data extraction from Tier-1 agentic codebases, LoRA fine-tuning with Unsloth, and cross-platform setup scripts (Windows, macOS, Linux).

python scripts/setup_env.py --extra dev
# See README.md on that branch

### MCP Apps exploration

**Branch:** `cursor/mcp-apps-exploration-ac82`

A mocked but fully wired MCP Apps gallery for Claude: live fleet map, operations dashboard, bottom sheets / dialogs, and interaction controls. Layout is host-controlled (`containerDimensions` + `inline` / `fullscreen` / `pip`), so the chat-column screenshot is not a protocol width cap.

**What it explores:** SEP-1865 UI resources, Claude design guidelines, CSP/sandbox limits, and which UX patterns actually feel native inside a conversation.

**Get started:**
```bash
git fetch origin cursor/mcp-apps-exploration-ac82
git checkout cursor/mcp-apps-exploration-ac82
cd mcp-apps-exploration
npm install && npm test && npm run preview
# See mcp-apps-exploration/README.md and RESEARCH.md
```

## How to contribute

1. **Pick or create a project branch** — new explorations should not land directly on `main`.
2. **Keep `main` as the index** — when you add a new project, open a PR to update this README with a row in the table and a brief section.
3. **Document on the branch** — each project owns its own README, setup guide, and architecture docs.
